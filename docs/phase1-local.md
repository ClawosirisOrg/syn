# Provisional Phase 1 fixture pipeline

These packages are local scaffolding, not an activated review service. There is no webhook acceptance, provider runner, GitHub comment publisher, or enabled live CLI path. Passing unit tests do not authorize repository activation.

- `internal/source` accepts explicitly selected, already acquired bytes. It normalizes and hashes the set, refuses binary/unsupported textual diffs and malformed target locators, but completeness and stability still depend on the caller’s authoritative acquisition. Pinned guidance now requires a nonserialized witness created by the fixed-origin GET-only reader, bound to approved repository/default branch, commit, path and exact blob bytes; a caller-supplied commit or serialized witness is **not** proof. A live run also requires an operator-approved branch and separate read-only credential, both absent from the fixture path. Recheck GitHub freshness before any later publication.
- `internal/safety` scans bounded normalized sources, returns no sanitized envelope for refusal/quarantine, and emits metadata-only finding references. Regex detectors are conservative but incomplete; a permitted public URL is data, never an instruction or permission to fetch. Custom in-process detectors have cooperative timeouts only: isolate them behind a killable outer deadline before accepting untrusted or live work.
- `internal/review.Execute` rechecks the locally built snapshot, runs preflight, validates source/context references, then passes only sanitized sources and bounded provenance-labelled context metadata to the deterministic fake. The fake has no provider, GitHub, shell, filesystem or network authority. This is not a real isolated model adapter; a future adapter must start fresh with a read-only, bounded context and no authoring memory or write credential.
- `internal/recordstore` accepts only strict metadata contracts into a private operator-owned root and does not store raw source bodies. `internal/fixture` derives deterministic fixture-only record/context identities, hashes caller-supplied delivery IDs before retention, stores minimal safety stops, and renders a bounded create preview only after a safe record is read back. Its explicit fixture-only runner, policy/profile and synthetic ownership identifiers must be rejected by every future live publisher. `internal/history` projects bounded prior canonical records as evidence; the fixture pipeline can include that projection so a changed prior record changes the context and record identity, and the fake receives exactly the stored context. Source references remain opaque, but completed-cycle count and latest-ID list require an authoritative index before live use. Live record identity, complete context provenance, freshness, and authenticated acquisition remain separate gates; the fixture preview and its `advisory_comment` contract value confer no publication authority.
- `internal/ownership` accepts only acquired pinned CODEOWNERS plus separately approved maintainer metadata; its deliberately narrow pattern subset and case-specific fallback refuse ambiguous owners. Caller approval flags still require authoritative operator provenance before live use.
- `cmd/syn` exposes offline `validate-config` and `review-fixture`; `serve`, `review-github` and `replay-delivery` return unavailable. The fixture deadline starts before local preprocessing, but a strict hard wall-clock cutoff for blocking filesystem I/O/custom detectors requires outer process isolation. Synthetic adversarial corpus provenance and limits are in [fixtures-provenance.md](fixtures-provenance.md).

Phase 0 CodeQL/signing/transport acceptance is still open. Phase 1 must pass the public issue #7 fixture/adversarial exit gate before webhook intake or live publication work is accepted.
